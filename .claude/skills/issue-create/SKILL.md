# 課題の起票

入力: 事象の説明（一文でよい）またはユーザーの声。

## 手順
1. **過去課題を検索する（完了済みを必ず含める）**
   ```bash
   gh issue list --state all --limit 50 --search "<キーワード> in:title,body"
   gh pr list --state merged --limit 30 --search "<キーワード>"
   ```
   候補は `gh issue view <番号> --json title,body,comments` で中身を読み、関連を判断する。
2. **原因を調査する**: 該当コードを読み、`git log -S "<識別子>"` で変更履歴を追う。
   原因コミットや原因課題を特定できたら記録する。特定できなければ「仮説」と明記する。
3. **重複確認**: 同一事象の未完了課題があれば起票せず、その課題にコメントを追加して終了。
4. **本文を作る**（`issue-body.md` に書く）
   ```markdown
   ## 事象
   <再現手順・期待結果・実際の結果>
   ## 原因（調査結果）
   <原因の箇所・コミット・関連課題。確度（確定/仮説）>
   ## 完了条件
   - [ ] <テストで確かめられる書き方>
   ## 関連課題
   - #<番号> <関係: 原因 / 同じ関数を変更 / 確認したが影響なし>
   ```
5. **起票する**
   ```bash
   gh issue create --title "<事象を一文で>" --body-file issue-body.md --label <bug|enhancement|feedback>
   rm -f issue-body.md
   ```
6. 起票した URL を示し、「内容の確認・担当と優先度の設定は人が行ってください」と伝えて終了する。

## 禁止
- 起票ついでにコードを修正しない
- 担当者（assignee）を AI が決めない
