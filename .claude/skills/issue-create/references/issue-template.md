# Issue 本文テンプレート
## 概要・背景
種別 / 利用者 / 目的 / 価値。優先度と見積りは根拠付きの提案。
## 再現手順・現状
環境、SHA、前提データ、番号付き手順、期待結果、実際の結果、頻度。
機能要望なら現状の利用フローと不足を記載。
## 調査結果
確定した事実と根拠（path:line、実行結果） / 仮説 / 未確認事項。
## スコープ・対象外
今回変更する範囲と、変更しない範囲。
## 受入基準
- [ ] AC-01: Given ... When ... Then ...
- [ ] AC-02: 異常入力 ... に対して ...
- [ ] AC-03: 境界値 ... に対して ...
## 設計図
`.claude/uml-guide.md` の判断表に従う。必要なら mermaid 図（不具合は現状とあるべき姿）。不要なら「図: 不要（理由）」。
## 影響範囲
画面 / API / DB / インフラ / 互換性 / データ移行。対象外は理由を書く。
## テスト計画
| AC | テスト種別 | 入力・手順 | 期待値 |
|---|---|---|---|
| AC-01 | 単体/結合/画面 | 具体値 | 具体値 |
## リスク・切戻し
副作用、検証環境、戻し方、データ変更の可逆性。
## 関連課題・依存
#番号 と関係。無ければ検索語と「該当なし」。
## 完了の定義
- [ ] ACに対応するテストが成功し実行結果をPRに記録
- [ ] 変更範囲外の不具合は別課題化
