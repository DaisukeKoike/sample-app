# sample-app のレビュー

対象: `git diff origin/main...HEAD`（引数で PR 番号が渡されたら `gh pr diff <番号>`）

次の観点ファイルに沿って、差分を1項目ずつ確認する:
- 共通: [checklists/common.md](checklists/common.md)
- 案件固有: [checklists/project.md](checklists/project.md)

## 出力形式
| 重要度 | 箇所 | 理由 | 修正案 |
|---|---|---|---|
| 高/中/低 | `path:line` | … | … |

- 該当なしの観点は「確認済み・指摘なし」とまとめて1行で書く
- 「高」は取り込み前に必須で直す。課題範囲外の指摘は「別課題候補」として分ける（自分では直さない）
- 最後に「観点ファイルに追加すべき新しい観点」があれば提案する

## 証拠付きレビュー
- ACごとに満足/未達/未確認を表にし、コード箇所とテスト結果を対応付ける。
- DBトランザクション、更新競合、日付境界、検索とCSVの条件一致、ページングの欠落・重複、0件集計を確認する。
- 既知バグを理由に対象外の新規不具合を黙認しない。対象外は別課題候補として報告する。
- 意図的バグの回帰テストが xfail のまま、または全バグOFFでのみ成功していないか確認する。
- 実行していないテストを成功と書かない。指摘には再現入力、期待値、実際値、path:lineを含める。
- Issue/PRの mermaid 図と実装が一致しているか確認する（状態値・遷移・呼び出し順・テーブル列）。不一致は「中」以上で指摘する。図が必要な変更なのに無い場合も指摘する。
